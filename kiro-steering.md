# Kiro Steering: Правила эффективной разработки

## 🎯 Основная цель
Писать чистый, рабочий код с первого раза, минимизируя количество итераций и расход кредитов. Качество важнее скорости, но скорость достигается за счет точности.

## 🚫 Принцип "Никаких предположений" (No Assumptions)
Если в задаче что-то не указано явно, не додумывай логику и не создавай лишних сущностей.
- **Действие:** Остановись и задай уточняющий вопрос в чат.
- **Исключение:** Если вопрос касается очевидного форматирования (отступы, кавычки) — используй настройки линтера/преттиера из проекта.
- **Зачем:** Лучше потратить 0.01 кредита на вопрос, чем 1.0 кредита на написание неправильной архитектуры, которую потом переделывать.

## 🧠 Принцип "Минимальных изменений" (Atomic Changes)
При внесении правок изменяй только то, что явно запрошено.
- Не рефактори соседние функции, даже если они "выглядят плохо".
- Не добавляй комментарии в код, если не было явной просьбы "задокументировать".
- Не меняй структуру файлов без команды.

## 📦 Управление зависимостями
- **Перед установкой пакета:** Проверь, не решит ли задачу встроенный модуль Node.js или существующая библиотека.
- **Вес пакета:** Если пакет необходим, предлагай легковесные альтернативы (например, `zustand` вместо `redux`, `dayjs` вместо `moment`).
- **Версии:** Устанавливай конкретные версии (без `^`), если проект не требует плавающих версий, чтобы избежать неожиданных поломок в будущем.

## ⚡️ Производительность (Быстрее)
1.  **Кэширование:** Используй мемоизацию там, где это уместно (React.memo, useMemo, useCallback), но только если есть реальная проблема рендера. Не оптимизируй преждевременно.
2.  **Асинхронность:** Все операции с файлами, сетью или базой данных делай асинхронными. Никаких `fs.readFileSync` в API роутах.
3.  **Бандл:** Следи за размером бандла. Если импортируешь из больших библиотек (например, lodash), импортируй конкретные функции: `import debounce from 'lodash/debounce'`.

## 📝 Стиль кода (Точнее)
- **Имена:** Функции называй с глаголов (`getUserData`, `handleSubmit`), переменные — существительными (`userList`, `isLoading`).
- **Типизация:** Используй TypeScript строго. Избегай `any`. Если тип сложный — выноси в отдельный `types.ts` или `interfaces.ts`.
- **Обработка ошибок:**
    - Все асинхронные функции должны быть обернуты в `try/catch` (или обрабатывать промисы через `.catch`).
    - Пользователю показывай человеко-понятное сообщение, в консоль логируй техническую ошибку.
- **Магические числа:** Никаких цифр в коде. Выноси их в константы с понятными именами (const MAX_RETRY_COUNT = 3).

## 💰 Экономия кредитов (Важно!)
1.  **Перед началом работы:** Всегда проверяй, открыт ли нужный файл и загружен ли контекст. Если файл не открыт — попроси пользователя открыть его, чтобы не гадать.
2.  **Анализ:** Перед тем как писать код, бегло просмотри существующий код в файле, чтобы соблюсти единообразие (табы/пробелы, стиль экспортов).
3.  **Один запрос — одна задача:** Если в запросе 3 пункта, а первый пункт неясен — уточни его, прежде чем делать остальные два.
