# Аудит производительности (Performance Checklist)

Если пользователь просит "оптимизировать приложение" или "сделать быстрее", используй этот чек-лист. Проверяй пункты по порядку.

## 🔍 Фронтенд (React/Next.js)

- [ ] **Рендеры:** Нет ли ненужных ререндеров? (Проверить компоненты, которые меняются, даже если пропсы не изменились).
    - *Решение:* `React.memo` для компонентов, `useMemo` для тяжелых вычислений, `useCallback` для функций.
- [ ] **Бандл:** Не импортируем ли мы всю библиотеку целиком?
    - *Решение:* Проверить импорты (lodash, antd, MUI).
- [ ] **Картинки:** Используется ли оптимизация изображений?
    - *Решение:* В Next.js использовать `<Image />`, в обычном React — ленивую загрузку (`loading="lazy"`).
- [ ] **Тяжелые списки:** Не рендерим ли мы 1000 элементов сразу?
    - *Решение:* Виртуализация (`react-window` или `react-virtualized`).
- [ ] **CSS-in-JS:** Не генерируется ли много классов на лету? (Может тормозить).

## 🔧 Бэкенд / API (Node.js)

- [ ] **N+1 запрос:** Нет ли цикла, который внутри себя делает запрос к базе?
    - *Признак:* Медленная загрузка списка.
- [ ] **Кэширование:** Кэшируются ли частые запросы? (Redis или in-memory cache).
- [ ] **Тяжелые операции:** Не делаем ли мы сложные вычисления на каждый запрос?

## ⚡️ Общие советы по оптимизации (Что предложить)

1.  **Lazy Loading:** Грузи компоненты только тогда, когда они понадобились (React.lazy).
2.  **Debounce:** На поисковые запросы (чтобы не дергать сервер на каждое нажатие клавиши).
3.  **Память:** Нет ли утечек памяти? (Подписки в `useEffect` должны отписываться).
