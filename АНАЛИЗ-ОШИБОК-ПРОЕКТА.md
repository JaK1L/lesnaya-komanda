### 9. **ОТСУТСТВИЕ ПАГИНАЦИИ**

**Приоритет:** 🟠 ВЫСОКИЙ  
**Файлы:**
- `backend/app/routes/admin.py` (list_events, list_news, list_users)
- `backend/app/routes/users.py` (get_players)

**Проблема:**
```python
@router.get("/users")
async def list_users(db):
    rows = await db.fetch("SELECT * FROM users ORDER BY last_seen DESC")
    return rows  # Может вернуть 10000+ записей
```

**Последствия:**
- Медленные запросы при большом количестве данных
- Высокое потребление памяти
- Таймауты на фронтенде
- Плохой UX

**Решение:**
```python
@router.get("/users")
async def list_users(
    db,
    page: int = 1,
    limit: int = 50,
    max_limit: int = 100
):
    limit = min(limit, max_limit)
    offset = (page - 1) * limit
    
    rows = await db.fetch(
        "SELECT * FROM users ORDER BY last_seen DESC LIMIT $1 OFFSET $2",
        limit, offset
    )
    total = await db.fetchval("SELECT COUNT(*) FROM users")
    
    return {
        "items": rows,
        "total": total,
        "page": page,
        "pages": (total + limit - 1) // limit
    }
```

### 10. **N+1 QUERY PROBLEM**

**Приоритет:** 🟠 ВЫСОКИЙ  
**Файлы:**
- `backend/app/routes/users.py`
- `backend/app/services/profile_service.py`

**Проблема:**
```python
# Получаем всех пользователей
users = await db.fetch("SELECT * FROM users")

# Для каждого пользователя делаем отдельный запрос
for user in users:
    achievements = await db.fetch(
        "SELECT * FROM achievements WHERE user_id = $1", 
        user['id']
    )
```

**Последствия:**
- 1 + N запросов вместо 1-2
- Медленная загрузка страниц
- Высокая нагрузка на БД

**Решение:**
```python
# Один запрос с JOIN
users_with_achievements = await db.fetch("""
    SELECT 
        u.*,
        json_agg(a.*) as achievements
    FROM users u
    LEFT JOIN achievements a ON a.user_id = u.id
    GROUP BY u.id
""")
```

### 15. **ОТСУТСТВИЕ КЭШИРОВАНИЯ**

- Высокая нагрузка на БД

**Решение:**
```python
from functools import lru_cache
from datetime import datetime, timedelta

# In-memory кэш
cache = {}
cache_ttl = {}

async def get_leaderboard_cached():
    now = datetime.now()
    if 'leaderboard' in cache and cache_ttl.get('leaderboard', now) > now:
        return cache['leaderboard']
    
    data = await db.fetch("SELECT * FROM users ORDER BY rating DESC LIMIT 100")
    cache['leaderboard'] = data
    cache_ttl['leaderboard'] = now + timedelta(minutes=5)
    return data
```

### 19. **ОТСУТСТВИЕ GRACEFUL SHUTDOWN**

**Приоритет:** 🟡 СРЕДНИЙ  
**Файлы:**
- `backend/app/main.py`
- `bot/main.py`

**Проблема:**
- Нет обработки сигналов завершения (SIGTERM, SIGINT)
- Соединения с БД не закрываются корректно
- Возможна потеря данных при перезапуске

**Решение:**
```python
import signal
import sys

async def shutdown():
    """Graceful shutdown"""
    print("Shutting down...")
    await database.disconnect()
    print("Database connections closed")

def signal_handler(sig, frame):
    asyncio.create_task(shutdown())
    sys.exit(0)

signal.signal(signal.SIGINT, signal_handler)
signal.signal(signal.SIGTERM, signal_handler)
```

### 27. **Participants хранятся как INTEGER[]**
**Файл:** `backend/app/routes/admin.py`

**Проблема:**
```sql
participants INTEGER[] DEFAULT '{}'
```

Это денормализация, лучше использовать отдельную таблицу.

**Решение:**
```sql
CREATE TABLE event_participants (
    id SERIAL PRIMARY KEY,
    event_id INTEGER REFERENCES events(id) ON DELETE CASCADE,
    user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
    registered_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(event_id, user_id)
);
```

### 28. **Отсутствие soft delete**
**Файлы:** Все DELETE операции

**Проблема:**
```python
await db.execute("DELETE FROM events WHERE id = $1", event_id)
```

Данные удаляются безвозвратно.

**Решение:**
```python
# Добавить колонку deleted_at
ALTER TABLE events ADD COLUMN deleted_at TIMESTAMP;

# Soft delete
await db.execute(
    "UPDATE events SET deleted_at = NOW() WHERE id = $1",
    event_id
)

# Фильтровать удаленные
SELECT * FROM events WHERE deleted_at IS NULL
```
